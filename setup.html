BZX Backend Setup Guide

Follow these steps to connect your Supabase backend. Takes about 15 minutes, completely free.

Step 1 — Create Supabase Project

1
Go to supabase.com → Sign Up (free)

Click "New Project" → name it bzx-market → pick any region → set a database password → Create.

Wait ~2 minutes for it to provision.

Step 2 — Get Your Keys

2
Project Settings → API

Copy two values:

  • Project URL — looks like https://xxxx.supabase.co
  • anon public key — long string starting with eyJ…

Paste them into all 3 files replacing YOUR_SUPABASE_URL and YOUR_SUPABASE_ANON_KEY:

const SUPABASE_URL = 'https://xxxx.supabase.co';
const SUPABASE_ANON_KEY = 'eyJhbGc...';

Files to update: market_4.html, login.html, dashboard.html

Step 3 — Create Database Tables

3
Go to SQL Editor in Supabase → paste and run this SQL: 
-- Profiles (one per user)
create table profiles (
  id uuid references auth.users primary key,
  ign text,
  role text,
  email text,
  created_at timestamptz default now()
);
alter table profiles enable row level security;
create policy "Users can read own profile" on profiles for select using (auth.uid() = id);
create policy "Users can update own profile" on profiles for update using (auth.uid() = id);
create policy "Users can insert own profile" on profiles for insert with check (auth.uid() = id);

-- Player cards
create table player_cards (
  id uuid default gen_random_uuid() primary key,
  user_id uuid references auth.users,
  ign text,
  uid text,
  role text,
  rank text,
  kd numeric,
  win_rate numeric,
  matches integer,
  price numeric default 0,
  skills text,
  bio text,
  social text,
  availability text,
  whatsapp text,
  tier text default 'starter',
  active boolean default true,
  created_at timestamptz default now()
);
alter table player_cards enable row level security;
create policy "Anyone can read cards" on player_cards for select using (true);
create policy "Owner can update card" on player_cards for update using (auth.uid() = user_id);
create policy "Owner can insert card" on player_cards for insert with check (auth.uid() = user_id);

-- Hire requests
create table hire_requests (
  id uuid default gen_random_uuid() primary key,
  hirer_id uuid references auth.users,
  hirer_name text,
  player_id uuid references auth.users,
  player_name text,
  tournament text,
  matches text,
  urgency text,
  note text,
  amount numeric default 0,
  status text default 'pending',
  paid_at timestamptz,
  created_at timestamptz default now(),
  updated_at timestamptz
);
alter table hire_requests enable row level security;
create policy "Hirer sees own requests" on hire_requests for select using (auth.uid() = hirer_id or auth.uid() = player_id);
create policy "Hirer can create request" on hire_requests for insert with check (auth.uid() = hirer_id);
create policy "Player can update status" on hire_requests for update using (auth.uid() = player_id or auth.uid() = hirer_id);

-- Messages
create table messages (
  id uuid default gen_random_uuid() primary key,
  sender_id uuid references auth.users,
  receiver_id uuid references auth.users,
  thread_id text,
  content text,
  type text default 'chat',
  read boolean default false,
  created_at timestamptz default now()
);
alter table messages enable row level security;
create policy "Participants can read messages" on messages for select using (auth.uid() = sender_id or auth.uid() = receiver_id);
create policy "Users can send messages" on messages for insert with check (auth.uid() = sender_id);
create policy "Receiver can mark read" on messages for update using (auth.uid() = receiver_id);

✅ Run this once — all tables are created.

Step 4 — Enable Realtime

4
Database → Replication → enable these tables:
  • ✅ hire_requests
  • ✅ messages

This makes hire notifications and messages appear live without refreshing.

Step 5 — Enable Google Login (optional)

5
Authentication → Providers → Google → Enable

Go to console.cloud.google.com → create OAuth credentials → paste Client ID & Secret into Supabase.

Callback URL to add in Google Console: https://xxxx.supabase.co/auth/v1/callback

Step 6 — Set Your UPI ID

6
In dashboard.html, find and replace: 
const BZX_UPI_ID = 'YOUR_UPI_ID@upi';

Replace with your actual UPI ID (e.g. yourname@paytm or 9876543210@ybl)

This is shown to hirers when a player accepts their request.

Step 7 — Deploy to Netlify

7
Put all 4 files in one folder:
  • market_4.html → rename to index.html
  • login.html
  • dashboard.html
  • setup.html (this file, optional)

Go to app.netlify.com/drop → drag the folder → done.

Add your Netlify URL to Supabase: Authentication → URL Configuration → Site URL

✅ Your site is live!

How the Hire Flow Works

End-to-end flow:
  1. Hirer logs in → clicks "Hire Now" on a player card
  2. Hire request saved to Supabase → player gets a live notification in their Dashboard
  3. Player clicks Accept → a message is auto-sent to the hirer with your UPI ID and amount
  4. Hirer pays via UPI → clicks "I've Paid" in their Dashboard
  5. Match is confirmed ✅ — both see "PAID" status
  6. They can message each other in the Messages tab throughout
⚠️ Never share your Supabase service_role key anywhere in the frontend. The anon key shown here is safe — it only gives access as per your RLS policies.
